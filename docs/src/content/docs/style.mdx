## Query features

The controller's <Api of="MapController.queryRenderedFeatures" display="queryRenderedFeatures()" />
finds the features that the map drew at a point, front first, such as the base
style's features near a click. A click's `point` is on the map, as queries take
it, and `hitPadding` widens the query to a square around it. The content's own
layers take [clicks](/maplibre-arkui/gestures/#clicks) without a query.

The controller's <Api of="MapController.querySourceFeatures" display="querySourceFeatures()" />
finds the features of a source in the tiles that it has loaded. Both resolve
`undefined` while no map shows a frame.

## The FFI map

For what the library doesn't cover yet, such as feature state, clusters, or the
style's own sources and layers,
<Api of="MapController.withFfiMap" display="withFfiMap()" /> lends a callback
the FFI map, a `MapHandle`, and its render session, a `RenderSessionHandle`.
Their API is MapLibre Native FFI's: see its [TypeScript reference]. Import their
types from `@maplibre/native-ffi`, at the version that the library depends on.

The callback runs at once. Send the map's commands in it, and await their
promises after it returns: the map and the session are only lent until then.

The library owns the style, the camera padding, the camera bounds, the
runtime's event handler, and the map's event mask, so don't change them through
the FFI map. Change the style through the map's `style`, so the map adds its
content again.

## What the next style keeps

A new style starts from its own document. It doesn't keep what the app added
through the FFI map, such as sources, layers, images, or feature state, so add
it again in `onStyleLoaded`, or declare it as
[content](/maplibre-arkui/content/), which the map adds to each style.

On an idle map, a feature state change draws only from the frame after the one
that applies it; until FFI fixes that, request one, as the demo's style page
does with `map.discarding.requestRepaint()` from a delayed frame callback
([maplibre-native-ffi#1706]).
