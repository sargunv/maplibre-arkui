Maps and snapshots load their styles, tiles, and other resources through a
<Api of="MapRuntime" />, which holds the cache and decides how requests load.
They share the default runtime, from
<Api of="MapRuntime.getDefault" display="MapRuntime.getDefault()" />, unless
the app passes its own.

A runtime that the app creates holds its cache in memory unless it has a
`cachePath`. Keep it in a field, pass it to each map and snapshot that uses it,
and release it once they're gone.

reason: a tile that isn't found draws nothing, and MapLibre tries again after
server and connection failures.

## Offline regions

The default runtime keeps its cache database, `maplibre-cache.db`, in the app's
files directory, so offline regions last between launches. The runtime's
<Api of="MapRuntime.createOfflineRegion" display="createOfflineRegion()" /> stores
a region, and its `startDownload()` downloads it. Its `status` is observable,
so a component shows the progress as it goes:

<Code code={region(examples, "offline")} lang="ts" />

Maps on the runtime use the region's resources once they load its style URL,
also while the device is offline.
<Api of="MapRuntime.getOfflineRegions" display="getOfflineRegions()" /> lists
the regions of earlier launches.

## Connectivity

While the device has no network, MapLibre starts no requests and shows what its
cache and offline regions hold; the requests wait until the device connects
again. To follow the device, the library needs
`ohos.permission.GET_NETWORK_INFO` (see
[Getting started](/maplibre-arkui/getting-started/)); without it, MapLibre
always tries the network. To keep maps offline, or online, whatever the device
does, set a mode with
<Api of="MapRuntime.setConnectivityMode" display="MapRuntime.setConnectivityMode()" />.
The mode applies to every runtime of the app.
