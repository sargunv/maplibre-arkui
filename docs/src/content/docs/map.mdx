<Api of="MaplibreMap" /> fills the size its parent gives it. The map creates its
FFI map when it appears and releases it when it disappears. Pages in the
background need no code, since the map draws only while its window shows.

## The style

The map's <Api of="MaplibreMap.style" display="style" /> is a URL, or a style
document as a `Record<string, Object>` with the [style spec]'s keys. A new value
loads the new style. A document that `build()` writes anew loads only when its
JSON changes, so the map doesn't load it again on each build.

## Events

The map's events tell the app what happens on it:

- `onStyleLoaded`: the style has loaded, with the map's content (see
  [The style API](/maplibre-arkui/style/)).
- `onStyleImageMissing`: the style names an image that it lacks, which the app
  can give (see [Images the style lacks](/maplibre-arkui/style/#images-the-style-lacks)).
- `onMapIdle`: the map has drawn everything that the view needs, and has
  nothing left to load or animate, such as once a style and its tiles load.
- `onFrameRendered`: the map drew a frame, with how long it took.
- `onCameraMoveStart` and `onCameraIdle`: the camera left rest, and came to
  rest again.
- `onGestureStart` and `onGestureEnd`: the user started and ended a gesture,
  which ends after its momentum and its snap (see
  [Gestures](/maplibre-arkui/gestures/)).
- The clicks (see [Clicks](/maplibre-arkui/gestures/#clicks)).
- `onError`: something failed (see [Errors](/maplibre-arkui/errors/)).

The controller shows the camera's state too: `cameraMoving` is true from
`onCameraMoveStart` until `onCameraIdle`, and `cameraMoveReason` says what
moved the camera last, the user's gesture or the app (see
[The camera](/maplibre-arkui/camera/#while-the-camera-moves)). The camera's
events keep to these rules:

- The controller's state changes first, and then the event runs.
- Each `onCameraMoveStart` is followed by exactly one `onCameraIdle` before
  the next, unless the map leaves in the middle of the move. Then
  `cameraMoving` turns false without an `onCameraIdle`.
- A jump is a move that starts and ends at once, as is the camera that a map
  starts with.
- A gesture's move starts after its `onGestureStart`, and ends after its
  `onGestureEnd`. A gesture that starts while the camera moves takes the move
  over, without another `onCameraMoveStart`.

The map calls each event on the UI thread, so a handler can change the page's
state. When a handler throws, the map logs the exception and goes on: the other
handlers still run, and a click handler that throws doesn't consume the click.

## Camera limits

`cameraBounds` limits where the camera goes: an area that its center stays
within, and ranges of zoom and pitch (see <Api of="CameraBoundsOptions" />).
Each limit that it leaves out takes its default, so removing one puts the
default back. Invalid limits, such as a minimum zoom above the maximum, go to
`onError`, and the map keeps the limits it had.

`runtime` takes a <Api of="MapRuntime" /> of the app's own, for another cache or
other request handling (see [Requests](/maplibre-arkui/requests/)).

[style spec]: https://maplibre.org/maplibre-style-spec/
